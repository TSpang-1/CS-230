## CS 230 Portfolio Reflection

**Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?**

The Gaming Room was the client for this project. They already had an Android game called Draw It or Lose It and wanted to expand it so that it could work across multiple different platforms. The game lets teams compete by guessing images as they are displayed. The software needed to support multiple games, teams, and players while making sure that the names were also unique. The client also wanted the application to work as a web-based system that could be accessed from different devices and operating systems.

**What did you do particularly well in developing this documentation?**

I think I did well comparing the different operating platforms and explaining which one would work best for the client. I considered Linux, Windows, macOS, and mobile devices instead of focusing on just one option. I also tried to connect my recommendations to what The Gaming Room actually needed instead of simply listing the advantages and disadvantages for each platform.

**What about the process of working through a design document did you find helpful when developing the code?**

The design document helped me understand how the different parts of the application were supposed to work together before completely focusing on the code. Breaking the system down into areas like the operating platform, storage, memory, networking, and security made the whole application easier to understand. It also showed me why planning the structure of a program before development can prevent problems from coming up later on.

**If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?**

If I could revise one part, I would improve some of my earlier explanations of the different operating platforms. I would make the comparisons more specific to the needs of The Gaming Room and provide a little stronger reasoning for why one option would be better than another. I think this would make the document more useful to both the client and the developers.

**How did you interpret the user's needs and implement them into your software design? Why is it so important to consider the user's needs when designing?**

I focused on the client's goal of making the game available to users on multiple platforms. Because of this, I recommended a web-based approach that would allow different devices to communicate with the same server instead of creating a completely separate application for every single operating system. Considering the user's needs is important because a good application is not very useful if it does not solve the problems that the client actually has.

**How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?**

I approached the design by looking at the requirements first and then breaking the application down into smaller parts. I compared the possible platforms, considered how the different components would communicate, and looked at security, storage, and performance areas. In future projects, I would use a similar process but spend some more time planning the architecture before actually starting the development. I would also keep using diagrams and design documents since they make it easier to see how the pieces of an application are connected before writing all of the code.
